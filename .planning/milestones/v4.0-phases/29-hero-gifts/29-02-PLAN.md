New methods:
```javascript
BondSystem.giftWeekIndex(now) // Math.floor(now / GIFT_WEEK_MS); non-finite -> 0
BondSystem.giftPairCount(heroId, giftKey) // int from flags['gift_'+hero+'_'+giftKey]
BondSystem.giftWeekTotal(heroId, now) // rolled total; stale week reads as 0 (no write)
BondSystem.giveGift(heroId, giftKey, now?)
  // ORDER (consume LAST, only on success path):
  // 1. validate heroId/giftKey via _safeKey + known-hero check -> 'unknown'
  // 2. roster check: HERO_GIFTS[heroId] includes giftKey (absent table -> 'not_liked')
  //    non-roster giftKey -> 'not_liked' (covers non-gift items too)
  // 3. recruited? isRecruited false -> 'not_recruited'; benched (_isActiveInParty
  //    false, linger does NOT qualify) -> 'inactive'
  // 4. affinity already 100 -> 'maxed'
  // 5. tier lock: gift def minTier vs tierFor(valueFor) via _tierMeets ->
  //    'tier_locked' (needs: <required tier>)
  // 6. weekly roll: weekIdx; stored week != current -> treat total as 0 and
  //    reset on success; total >= CAP -> 'capped'
  // 7. diminishing: gain = GAINS[min(count,2)] or TAIL (count>=3)
  // 8. clamp: grant = min(gain, CAP - total, 100 - value); grant<=0 -> 'capped'/'maxed'
  // 9. consume: Economy.removeItemByName(foundName, 1) — find inventory item by
  //    giftKey first (name may differ from key); missing -> 'no_item' (check
  //    BEFORE any flag write; double-check after? single check suffices)
  //    NOTE: check no_item BEFORE step 8 writes — order: locate item early
  //    (step 5.5) but consume only at step 9 after all denials pass.
  // 10. write flags: pair count+1, week idx + total+=applied(via this.add result);
  //     affinity via this.add(heroId, grant) (canonical, respects active gate);
  //     if this.add applied < grant (race), top up? No — accept applied, still
  //     count the pair + cap by APPLIED amount.
  // returns { ok:true, applied, gain, count, tierUp, weekTotal } or
  //         { ok:false, reason, need? } with reasons:
  //         unknown | not_liked | not_recruited | inactive | maxed |
  //         tier_locked | capped | no_item
BondSystem.normalizeGifts(flags) // keep gift_<hero>_<giftKey> int 0..99 for
  // known heroes only (unknown giftKeys dropped ONLY if HERO_GIFTS table
  // present to validate against; absent table -> keep hero-scoped ints);
  // giftweek_<hero>/gifttotal_<hero> ints (week>=0, total 0..CAP*4 clamp);
  // proto-pollution keys dropped; all other flags verbatim (linger/combo pattern)
```
