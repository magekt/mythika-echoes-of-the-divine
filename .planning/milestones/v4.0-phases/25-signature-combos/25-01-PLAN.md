<name>Task 1: BondSystem combo contract (COMBOS, availability, potency, flags)</name>
<files>src/systems/bond.js</files>
<action>
Add a Phase 25 section to BondSystem (append before the module.exports guard; no existing behavior changes):

1. `COMBOS` table - exactly one entry per hero id (arjuna, bhima, karna, draupadi, hanuman). Each entry:
   `{ heroId, name, kind, base, statScale, flavor }` where kind is one of
   `'strike'` (arjuna precision duo strike), `'slam'` (bhima intercepting slam:
   single-target + party shield), `'volley'` (karna burst volley: all-enemy AoE),
   `'aegis'` (draupadi warding aegis: party heal + shield),
   `'leap'` (hanuman mountain-leap follow-up: single-target heavy + half splash).
   Names/flavor keep a respectful mythological tone (implementer's discretion).
   Suggested numbers (tune freely, tests assert shape not numbers):
   strike base 1.8 two hits, slam base 1.6 + shield 15, volley base 1.2 all foes,
   aegis heal 0.25 + shield 12, leap base 2.2 + 0.5 splash.
2. `comboFor(heroId)` - returns a COPY of the entry (mutating it must not affect
   the table), or null for unknown/hostile keys. Guard with _safeKey + known-ids.
3. `comboAvailable(heroId, orderedIds, playerId)` - returns
   `{ available, heroId, partnerId, reason }`. Rules: hero known + safe key;
   tier must be Legend (value >= 90, via valueFor+tierFor); hero must be
   combat-eligible (reuse `_isActiveInParty(heroId) || isLingering(heroId)`);
   partner resolves to playerId when it names a *different* active-party hero,
   else falls back to the first other active hero in orderedIds; partner must be
   a different id, active-party eligible, and present in orderedIds.
   Reasons: 'ok' | 'unknown' | 'not_legend' | 'hero_inactive' | 'no_partner'.
   Never throws; hostile input yields `{ available: false, reason: 'unknown' }`.
4. `comboPotencyFor(heroId, roleStatValue, weaponLvl, hasWeapon)` - pure helper
   returning `{ mult, bonus }` where `mult = base + statScale * max(0, roleStatValue)`
   and `bonus = hasWeapon ? 0.15 * max(1, floor(weaponLvl)) : 0`, i.e. effective
   multiplier `mult * (1 + bonus)`. Unarmed (hasWeapon false) yields bonus 0
   (base effect only). All inputs coerced safe (non-finite -> base effect).
5. Unlock flags - `comboSeen(heroId)` reads `flags['combo_'+heroId] === true`;
   `markComboSeen(heroId)` sets it once (returns `{ ok, first }`; hostile or
   unknown ids return `{ ok: false }`); `normalizeCombo(flags)` keeps only
   true-valued `combo_<knownHero>` flags, passes all other flags through
   verbatim, drops hostile keys. Mirrors the normalizeLinger pattern.
</action>
<verify>Node one-liner loads bond.js in vm with five-hero G.state: comboFor copy
semantics hold; comboAvailable gates Legend/active/partner; potency math matches
spec; hostile keys safe.</verify>
<done>COMBOS has exactly 5 entries (one per hero); availability/potency/flag
helpers behave per spec with zero changes to existing BondSystem behavior.</done>

<name>Task 2: Combat.performSignatureCombo + both-turns consumption</name>
<files>src/systems/combat.js</files>
<action>
Add Phase 25 authority to Combat (append near applyBondPassives; do not alter
existing formulas or Phase 14 contract call sites):

1. `startBattle`: reset `this.consumedTurns = {}` and `this.comboResults = []`
   alongside the existing bondBonuses reset.
2. `performSignatureCombo(heroClone, partnerClone, opts)` - canonical executor
   operating ONLY on battle clones. Steps:
   - Resolve heroId/partnerId; look up combo def via guarded
     `BondSystem.comboFor` when present, else fall back to an internal
     `SIGNATURE_FALLBACK` table (same five kinds) so combat works with
     BondSystem absent.
   - Determine role-stat value from the hero clone (`hero[roleStat]`,
     roleStat via BondSystem.roleStatFor or internal map) and weapon state
     (`weaponLvl`, `!!weaponEquipped`); compute potency via
     `BondSystem.comboPotencyFor` when present else the same formula inline.
   - Apply per kind using EXISTING primitives only (no new damage pipeline):
     strike/leap/slam/volley damage via `this.performAttack` per target with a
     synthetic skill `{ dmg: effectiveMult }` so crit/combo-count/shield/intercept
     hooks stay intact; aegis/slam shields via `applyBuff(target, 'shield', amt, 2)`;
     aegis heal as flat party heal fraction of maxHp.
   - Set `this.consumedTurns[partnerId] = true` (the hero's own turn is consumed
     by the caller advancing) and record `{ heroId, partnerId, kind, total }`
     in `this.comboResults` for scene log lines.
   - Guard everything in try/catch: invalid/dead/missing participants return
     `{ ok: false, reason }` without mutating battle state.
   - Return `{ ok: true, kind, name, total, lines }` where `lines` is 1-2
     human-readable strings for the EXISTING log band (scene decides display).
3. `nextTurn`: after incrementing, skip turnOrder entries whose
   `ref.id` is flagged in `consumedTurns` (delete the flag on skip so it costs
   exactly one turn), with the same dead-actor skip-loop hardening. Must not
   infinite-loop when all remaining entries are consumed (bounded tries).
4. `markComboSeen` bridge: after a successful combo, best-effort call
   `BondSystem.markComboSeen(heroId)` inside try/catch (G.state write allowed
   here - flags only, never stats). Absent BondSystem is fine.
</action>
