<action>
Append a Phase 26 section to bond.js (before the module.exports guard; no
existing behavior changes). Global name: `BeastBond`.

State shape (all under G.state.beastBond; hearts are DERIVED, never stored):
`{ xp: {beastId: n}, feed: {day, counts: {beastId: n}}, train: {day, counts: {beastId: n}}, trainCd: {beastId: timestampMs} }`

Constants (exact):
- `HEART_THRESHOLDS = [0, 30, 80, 160]` (heart 0/1/2/3)
- `BATTLE_XP = 8`, `FEED_XP = 11`, `PRANA_TRAIN_XP = 6`, `GOLD_TRAIN_XP = 14`
- `FEED_GOLD_BASE = 20`, `GOLD_TRAIN_BASE = 40`, `PRANA_COST = 25`
- `FEED_CAP = 3`, `TRAIN_CAP = 5` (prana+gold share one pool per beast per day)
- `GOLD_TRAIN_CD_MS = 300000` (5 minutes, per beast)
- Day-equivalent: `Math.floor(now / 86400000)`; `BeastBond._now` returns
  `Date.now()` and tests may override it.

Functions (all never-throw; hostile input yields safe defaults):
1. `heartFor(xp)` - thresholds lookup, clamped input, returns 0-3.
2. `xpFor(beastId)` / `get(beastId)` - read-only; unknown/hostile ids yield
   `{ xp: 0, heart: 0 }`. `get` returns `{ xp, heart }`.
3. `_state()` - returns G.state.beastBond object, creating the healed shape
   when missing (never throws when G is absent; uses a detached fallback).
4. `_knownIds()` - SPIRIT_BEASTS keys when present, else null (allow-all).
5. `feedGoldFor(hearts)` / `trainGoldFor(hearts)` - `Math.round(BASE *
   Math.pow(1.2, clamp(hearts,0,3)))`.
6. `isFeedItem(item)` - true when item is an object with a name and
   (`type === 'herb'` OR (`type === 'consumable'` AND `recipeId` string) OR
   name matches a HERB_GROWTH value name when HERB_GROWTH is present).
7. `addBattleXP(beastId)` - active-beast-agnostic +8 to xp[beastId]; returns
   `{ ok, xp, heart, heartUp }`. Unknown/hostile beastId yields `{ ok: false, reason: 'unknown_beast' }`.
8. `feed(beastId, itemName)` - order: validate beast; validate itemName resolves
   to an eligible feed item in inventory (Economy.getItemCount > 0 and
   isFeedItem); check daily feed cap; check gold via (G.state.gold >= cost);
   then mutate ONLY via Economy.removeItemByName(itemName, 1) and
   Economy.spendGold(cost); on mutation failure roll back nothing (no partial
   writes: check-then-mutate atomically); add FEED_XP; bump feed count.
   Returns `{ ok: true, xp, heart, heartUp, item, gold }` or `{ ok: false, reason }`
   with reason in {unknown_beast, no_item, capped, no_gold}.
9. `pranaTrain(beastId)` - validate beast; check shared train cap; check
   prana >= 25; decrement G.state.prana directly; add PRANA_TRAIN_XP; bump
   train count. Reasons: {unknown_beast, capped, no_prana}. No cooldown.
10. `goldTrain(beastId)` - validate beast; check shared train cap; check
    cooldown (trainCd[beastId] + 300000 > now yields `cooldown` with
    `retryMs`); check gold; Economy.spendGold; add GOLD_TRAIN_XP; bump train
    count; set trainCd. Reasons: {unknown_beast, capped, cooldown, no_gold}.
11. `statusFor(beastId)` - read-only view for scenes: `{ xp, heart,
    nextAt (threshold or null at heart 3), feedLeft, trainLeft, goldCdMs }`.
    Never mutates.
12. `normalize(candidate)` - heals a beastBond candidate: drops hostile keys
    and unknown beast ids from xp/counts/trainCd, clamps xp to 0..9999 and
    counts to 0..99, coerces day/trainCd numbers safe, returns healed object
    with exactly keys {xp, feed, train, trainCd}. Non-object input yields the
    empty shape.

Node export guard: extend the existing `module.exports` check to also export
BeastBond without breaking `BondSystem` export shape.
</action>
