<feature>
  <name>Legacy-safe world-state save migration and round trip</name>
  <files>src/systems/save.js, tests/world_state.test.js</files>
  <behavior>
    - Legacy input: a version-1 save with no `world` branch loads with canonical world defaults and retains player, party, currencies, flags, encounters, and zone progress.
    - Partial input: valid supplied branches/entries survive while missing branches are rebuilt from defaults.
    - Malformed input: arrays/primitives/non-finite values/unsafe keys inside `world` are repaired or dropped; `SaveSystem.load()` returns success rather than throwing.
    - Round trip: populate every world domain, save to mocked localStorage, reset state, load, and deep-compare the observable canonical world state.
    - Replay safety: discovered/notified landmarks, recorded transitions, and resolved events remain recorded after reload; a duplicate mutation remains a no-op and cannot overwrite the first outcome.
    - Regression: unrelated valid top-level progress remains unchanged by world normalization.
  </behavior>
  <implementation>
Use RED→GREEN→REFACTOR. Expand the Plan 06-01 test harness first and confirm the new migration/round-trip assertions fail. Then call `WorldState.normalize(G.state.world)` from `SaveSystem.migrate()` after the default-state overlay has occurred and before load returns control to gameplay. If `WorldState` is unexpectedly unavailable, use the canonical default from `G.createDefaultState().world` rather than leaving malformed data in place; keep direct-script loading robust. Do not increment or reject the existing version-1 save envelope: this change is backward-compatible nested-state migration. Do not mutate unrelated fields, replay notifications, invoke scene code, or convert one-time records during load. Refactor after all tests pass.
