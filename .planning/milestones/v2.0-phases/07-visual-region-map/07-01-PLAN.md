## Requirements (from REQUIREMENTS.md)
REQ-013 — Distinct Visual Regions:
  - The Travel Map presents existing zones as spatial regions or nodes rather than only as a vertical list.
  - Each region is visually distinguishable while preserving its canonical name, realm, lock state, and completion progress.
  - Selecting a region clearly reveals its status and available next action.
  - No new zones are introduced.

REQ-019 — Mobile-First Map Interaction:
  - A tap selects the intended region and reveals its status and next available action
    without accidental activation during pan/scroll.
  - The full select, inspect, back/close, and enter flow works on the 400×720 touch viewport
    and with a desktop pointer.

## Existing zone data shape (zones.js)
Each zone: {id, name, desc, reqLevel, reqZone, minLvl, maxLvl, realm, bgColor, explorationMax, ...}

## Existing zone access pattern (zone_access.js)
ZoneAccess.status(zoneId) returns {allowed, percentage, complete, reqLevel, reqZone}.
ZoneAccess lists the current state per zone.

## WorldState API surface (world_state.js)
WorldState.getRegion(zoneId) returns {value, control} or null.
G.state.world.regions is keyed by zoneId.

## Current travelMap.js pattern
Uses UI.Button factory for zone cards in a 2-column grid, grouped by realm.
Scroll-based navigation (scrollY, clampScroll, getContentTop/Height).
ZoneAccess.status(zoneId) drives visual state.
