<objective>
Reduce per-frame allocations and draw calls in the travel map scene. Replace the grid
background's 51 individual beginPath/stroke calls with a pre-rendered offscreen canvas,
cache per-frame computation results, and cull off-screen regions and connections.

Purpose: The living map now renders 6 region cells, connections, landmark/echo/event indicators, a 51-stroke grid background, and detail panels — all recomputing metrics, rects, text wrapping, and grid lines every frame. This plan eliminates the grid background as the single most expensive per-frame operation (per research), caches computation results to prevent ~15-20 small-object allocations per frame, and skips rendering for regions/connections outside the visible viewport.

Output: Optimized travelMap.js render pipeline with offscreen grid canvas, cached metrics, cached text wrapping, and viewport culling. New test file validating allocation behavior and grid caching.
</objective>

The grid background in `renderMapTexture` (lines 404-420) is the single most expensive per-frame operation: ~51 individual `beginPath/moveTo/lineTo/stroke` calls per frame. Pre-render the grid to an offscreen canvas and replace with a single `drawImage` call.

1. **Add offscreen canvas fields to `data`** initialization:
   ```javascript
   _gridCanvas: null,
   _gridCtx: null,
   _gridW: 0,
   _gridH: 0,
   ```

2. **Add `_buildGridCanvas` method** to the scene object:
   ```javascript
   _buildGridCanvas: function(viewport) {
     const gw = G.W + 48;
     const gh = viewport.h + 48;
     // Only recreate if size changed (resize)
     if (!this.data._gridCanvas || this.data._gridW !== gw || this.data._gridH !== gh) {
       this.data._gridCanvas = document.createElement('canvas');
       this.data._gridCanvas.width = gw;
       this.data._gridCanvas.height = gh;
       this.data._gridCtx = this.data._gridCanvas.getContext('2d');
       this.data._gridW = gw;
       this.data._gridH = gh;
     }
     const gctx = this.data._gridCtx;
     gctx.clearRect(0, 0, gw, gh);
     gctx.strokeStyle = R.colors.borderHairline;
     gctx.lineWidth = 1;
     // Draw grid lines at base position (drift = 0)
     for (let x = 0; x < gw; x += 24) {
       gctx.beginPath();
       gctx.moveTo(x, 0);
       gctx.lineTo(x, gh);
       gctx.stroke();
     }
     for (let y = 0; y < gh; y += 24) {
       gctx.beginPath();
       gctx.moveTo(0, y);
       gctx.lineTo(gw, y);
       gctx.stroke();
     }
   },
   ```

3. **Replace `renderMapTexture`** (lines 404-421). Instead of 51 individual strokes, use the offscreen canvas:
   ```javascript
   renderMapTexture: function(ctx, viewport) {
     const reduced = R.reducedMotion ? R.reducedMotion() : false;
     const drift = reduced ? 0 : (performance.now() / 7000) % 24;
     this._buildGridCanvas(viewport);
     ctx.drawImage(this.data._gridCanvas, -24 + drift, viewport.y - 24 + drift);
   },
   ```

   The offscreen canvas is (viewport.w + 48) × (viewport.h + 48) — 24px padding on each side covers the full drift range (0–24px). The drawImage offset shifts the entire pre-rendered grid by the current drift amount, producing smooth animation identical to the original.

   The grid is in screen-space coordinates (not map-space), so pan position does NOT affect the grid canvas. The canvas only needs recreation on viewport resize (extremely rare).

4. **Clear grid canvas in `resetState()`**. Add:
   ```javascript
   this.data._gridCanvas = null;
   this.data._gridCtx = null;
   this.data._gridW = 0;
   this.data._gridH = 0;
   ```

5. **No additional tests needed** for this task — the existing `travel_map_perf.test.js` from task 1 already verifies render behavior. The grid caching is a transparent performance optimization with no behavioral change. Visual verification will be covered by the human checkpoint in plan 12-02.
