<feature>
  <name>Canonical and idempotent world-state contract</name>
  <files>src/engine/game.js, src/systems/world_state.js, index.html, tests/world_state.test.js</files>
  <behavior>
    - Default: `G.createDefaultState().world` contains plain-object branches for `regions`, `landmarks.discovered`, `landmarks.notified`, `influence`, `narrativeEchoes`, `events.active`, `events.resolved`, and `transitions`.
    - Normalization: null, arrays, primitive branches, non-finite influence, and unsafe keys are repaired or dropped without throwing; valid keyed records survive.
    - Bounds: influence values are finite and clamped to the documented system range; control values are normalized to the allowed domain selected in this plan and stated in code comments.
    - Idempotency: recording an existing landmark discovery or transition returns an unchanged result; resolving an already-resolved event cannot overwrite its original outcome.
    - Separation: query helpers do not mutate state; mutation helpers are the only supported write boundary.
  </behavior>
  <implementation>
Use RED→GREEN→REFACTOR. First build `tests/world_state.test.js` with Node built-ins (`node:test`, `assert`, `fs`, `vm`) and browser-global stubs; verify it fails before implementation. Then add the exact default subtree to `createDefaultGameState()` and implement `WorldState` as a global namespace object matching the repository's system pattern. Use keyed objects, clone accepted metadata into fresh plain objects, reject `__proto__`/`constructor`/`prototype`, preserve valid unknown identifiers, and never derive one-time writes from render/read access. Register the script after zone data and before `save.js`. Do not add npm tooling or a dependency. Refactor only after all cases pass.
  </implementation>
</feature>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage/imported save → `WorldState.normalize` | User-editable persisted JSON enters trusted game state. |
| future gameplay systems → `WorldState` mutations | Multiple global systems will write regional and event state through one API. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | T | `WorldState.normalize` | mitigate | Rebuild plain branches, reject unsafe keys, validate record types, and clamp finite numeric influence values. |
| T-06-02 | E | keyed world records | mitigate | Block `__proto__`, `constructor`, and `prototype` before copying keys or metadata. |
| T-06-03 | R | one-time transitions/events | mitigate | First-write-wins records and explicit boolean return values make duplicate mutation attempts observable and non-destructive. |
| T-06-04 | D | malformed/unbounded save objects | mitigate | Ignore invalid entries and retain keyed, serializable records rather than executing or recursively traversing arbitrary prototypes. |
</threat_model>
