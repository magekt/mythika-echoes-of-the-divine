<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| script loading → progress tracking | Untrusted script loading status (success/failure) crosses here |
| input event processing → Input._ready check | Potentially unsafe input processing guarded by readiness flag |
| DOM manipulation → overlay updates | Cross-site scripting risk if error messages contain untrusted data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-01 | S | Script error messages | mitigate | Error messages are hardcoded strings, not derived from script content |
| T-43-02 | T | Input._ready race condition | mitigate | Atomic boolean flag; worst case is slight delay in input enablement |
| T-43-03 | I | Progress tracking manipulation | accept | Progress tracking is client-side only; no security implications |
| T-43-04 | R | Loading overlay bypass | mitigate | Overlay dismissal requires two independent conditions (frame count + input ready) |
| T-43-05 | D | Script loading DoS | accept | Network-level issue; game shows error and allows refresh |
| T-43-06 | E | Error information disclosure | mitigate | Error messages are generic and don't reveal system details |
</threat_model>
