# Phase 37 Plan 01: Guided First-Battle Callout System (ONB-01)

## Objective
A first-time player entering zone exploration for the very first time gets 5 dismissable gold callouts explaining the combat loop: encounter tap → attack button → turn order → rewards → explore more. Callouts fire only once (`G.state.tourSeen.firstBattle`), advance on tap, and never block input.

## Grey-Area Decision (auto-answered)
**Auto:** Callouts are drawn on `zoneExploration.js` only (not combat scene) — combat already has its own UI; the tour teaches pre-combat context. `G.state.combatCount` is incremented after each combat in the existing combat completion path. Tour is skipped if `G.state.combatCount > 0` OR if the current zone has `zoneProgress >= 100` (already cleared it before).

## Context
- `src/scenes/zoneExploration.js` — has `enter()`, `render(ctx)`, `update()`, uses `UI.Button`, `R.roundRect`, `R.colors`, `R.fonts`
- `src/systems/tour.js` does not exist yet
- `G.state` is the shared global state; `G.state.tourSeen = {}` is the persistence point
- `R.reducedMotion()` — if true, callouts appear instantly (no fade-in), still dismissable

## Files
- **create:** `src/systems/tour.js`
- **modify:** `src/scenes/zoneExploration.js`, `src/engine/game.js` (register `TourSystem` as global), save system hydration in `src/systems/save.js` if applicable

## Tasks

### Task 1: Create `src/systems/tour.js`
- `TourSystem` object with:
  - `TourSystem.start(tourId)` — checks `G.state.tourSeen && G.state.tourSeen[tourId]`; if already seen, returns false. For `'firstBattle'`: checks `G.state.combatCount === 0` OR unset, AND `G.state.zoneProgress && G.state.zoneProgress[currentZone] < 100`. If conditions met, sets internal `step = 0` and returns true.
  - `TourSystem.render(ctx)` — if active tour, draws current callout: a small gold-bordered rounded-rect (width = text width + 32px padding, height = 48px) positioned in upper-center area of canvas (below header, above content). Draws gold `R.colors.orange` border + dark bg. Step text from array of 5 callouts.
  - `TourSystem.update()` — tap advances step: `step++`. When `step >= 5`, sets `G.state.tourSeen.firstBattle = true` and deactivates.
  - `TourSystem.isActive` — boolean getter
- Callout text array (5 items, ≤12 words each):
  1. "Tap the enemy to begin your first battle"
  2. "Tap Attack to strike the enemy on your turn"
  3. "Turns alternate — watch the turn indicator above"
  4. "Claim your rewards when the battle ends"
  5. "Explore the zone to find more encounters"

### Task 2: Register TourSystem globally in `src/engine/game.js`
- Find where other systems are attached to `window` (look for `window.Combat = Combat` etc.)
- Add `window.TourSystem = TourSystem` in the same block
- Ensure `tour.js` is loaded before `game.js` in `index.html` script order (add `<script src="src/systems/tour.js"></script>` in the systems script block, after `src/systems/journey.js`)

### Task 3: Wire into `zoneExploration.js`
- In `enter()`: after zone setup, call `if (TourSystem.isActive || TourSystem.start('firstBattle'))` — just call `TourSystem.start('firstBattle')` (returns false if already seen or preconditions not met)
- In `render(ctx)`: call `TourSystem.render(ctx)` at the end of the render function
- In `update(dt)`: call `TourSystem.update(dt)` at the start of update

### Task 4: Save-state hydration
- In `src/systems/save.js` (or wherever `G.state` defaults are initialized), add: `G.state.tourSeen = G.state.tourSeen || {}`
- This ensures the flag persists across save/load
