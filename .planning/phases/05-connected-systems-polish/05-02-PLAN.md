## Loop Architecture (from codebase analysis)

**Ashram** → nav button 'Map' → **TravelMap** → zone select → **ZoneExploration** → encounter trigger roll → **EncounterScene** → origin: 'zoneExploration' → continue → back to **ZoneExploration** or **TravelMap**

**Ashram** → nav button 'Map' → **TravelMap** → zone select → **ZoneExploration** → enemy encounter → **CombatScene** → win → return to **ZoneExploration**

**ZoneExploration** (back button) → **TravelMap** → nav button 'Map' → **Ashram**

**Key gap**: EncounterScene.buildResult() does not currently show a "Continue" button after resolution — only the result panel is shown with no explicit next-action. Player must back out manually.

**Journey grant gap**: encounter.js grants journeys via `G.state.journeys.progress[id] = true` (line ~123) instead of routing through `JourneySystem.start()`. This bypasses any validation or notification JourneySystem.start provides.
</context>

<task type="auto">
  <name>task 2: Route encounter journey grants through JourneySystem.start</name>
  <files>src/systems/encounter.js</files>
  <action>In `EncounterSystem.choose()` (src/systems/encounter.js), the journey grant block (currently around lines 119-122) directly sets `G.state.journeys.progress[id] = true`. Replace this with a call to `JourneySystem.start()` so journey grants are routed through the canonical API:

  Current code (approximate):
  ```js
  if (r.journey) {
    G.state.journeys.progress[r.journey] = true;
    granted.push({ type: 'journey', id: r.journey });
  }
  ```

  Replace with:
  ```js
  if (r.journey) {
    if (typeof JourneySystem !== 'undefined' && JourneySystem.start) {
      const jResult = JourneySystem.start(r.journey);
      if (jResult) {
        granted.push({ type: 'journey', id: r.journey });
      }
    } else {
      // Fallback if JourneySystem not loaded — preserve existing behavior
      if (!G.state.journeys) G.state.journeys = { active: null, progress: {} };
      G.state.journeys.progress[r.journey] = true;
      granted.push({ type: 'journey', id: r.journey });
    }
  }
  ```

  This ensures:
  - JourneySystem.start validates the journey exists before granting
  - Any notifications JourneySystem.start shows (Notify.show) are displayed to the player
  - Fallback preserves backward compatibility if JourneySystem is not loaded (unlikely but safe)

  Do NOT modify any other reward branches (gold, karma, xp, etc.) — only the journey grant block.
  </action>
  <verify>
    <automated>grep -c 'JourneySystem.start' src/systems/encounter.js | grep -v '^0$'</automated>
  </verify>
  <done>Encounter journey grants route through JourneySystem.start instead of direct state mutation</done>
