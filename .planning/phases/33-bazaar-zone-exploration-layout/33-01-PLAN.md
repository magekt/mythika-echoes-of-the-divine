## Locked Decision Reference

**D-02 (LOCKED):** Bazaar list rows use variable height with text wrapping. Long names or descriptions wrap to a second line instead of truncation. All information stays visible. Row height is computed per-item based on wrapped content (min 1 line, max 3 lines). `UI.ScrollList` currently hard-codes a fixed `itemHeight: 34` in all callers; this plan modifies the list to accept and use a `getItemHeight` callback that returns the computed height for each item at render time.

**D-03 (LOCKED):** Downstream discretion from Phase 32/harness data. Consult layout_harness.test.js and verify_matrix.py for measurement contracts.

  <files>src/ui/list.js</files>
  <action>
Modify `UI.ScrollList` to support dynamic item heights:

1. Add optional `getItemHeight` callback to opts (defaults to `null`).
2. Modify `setItems()` to compute `contentHeight` using `getItemHeight` if provided:
   - If `getItemHeight` exists, sum each item's computed height + gaps + padding
   - If not provided, fall back to fixed `itemHeight * items.length + gaps + padding`
3. Modify `handleInput()` to iterate through items and track cumulative Y positions, using each item's individual height instead of assuming fixed `itemHeight`.
4. Modify `render()` to pass each item's computed height to `onRenderItem` so the rendering function knows exactly where the item box ends.
5. Preserve scrolling math (don't break scroll velocity or bounds clamping).

Rationale: Allows Bazaar and other scenes to define how tall each row should be based on its content without duplicating layout logic.

Per D-02, this is the foundation for wrapping text in Bazaar rows. The callback allows Bazaar to say "this item needs 3 lines" when wrapped text demands it.
